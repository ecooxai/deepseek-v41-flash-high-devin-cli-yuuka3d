# Yuuka · Pajama Ver. — procedural 3D character

A fully procedural, from-scratch 3D character built for the web with **three.js**.
Nothing is loaded from disk or the network: every mesh is generated by code and
every texture is painted onto a 2D canvas at runtime.

* **Model / agent:** DeepSeek V4.1 Flash High · Devin CLI
* **Subject:** Yuuka — pajama version (reference: `docs/reference/yuukapa.png`)
* **Stack:** vanilla JS + three.js + esbuild. No framework, no 3D assets.

---

## Quick start

```bash
npm install          # three, esbuild, puppeteer-core (dev only)
npm run build        # bundles src/ -> dist/  (dist/ is committed for Pages)
npm run serve        # static server on http://127.0.0.1:8137
```

Open <http://127.0.0.1:8137/>. `npm run watch` rebuilds on change.

## Verification / screenshot tooling

Headless Chromium here has no working EGL, so the tools run Chromium under
Xvfb (the host has an Intel UHD 620 + Mesa, which does provide GLX).

```bash
node tools/shot.mjs out.png --view front --w 640 --h 1010   # render a view
node tools/probe.mjs --view face --w 640 --h 640 --at 320,340  # raycast report
```

`tools/shot.mjs` also forwards any query string on `--url`, which drives the
in-app debug switches:

| query | effect |
| --- | --- |
| `?view=front\|threeq\|side\|back\|face` | jump to a camera preset |
| `?solo=Name` | show only the subtree containing that object name |
| `?hide=A,B` | hide objects by name |
| `?nooutline=1` | drop every outline shell |
| `?flat=1` | normal-material preview (shape check) |

`textures.html` renders every procedural texture for inspection.

### Measuring instead of guessing

Three shell/node helpers exist because eyeballing a render against the
reference repeatedly sent the work in the wrong direction:

```bash
node tools/shot.mjs shots/sil.png --view front --w 700 --h 1200 \
     --url 'http://127.0.0.1:8137/index.html?bg=magenta&hud=0'
tools/overlay.sh shots/sil.png /tmp/ov.png 900   # reference | render | blend
tools/profile.sh shots/sil.png 26                # width profile, height-normalised
```

* `tools/overlay.sh` trims both images to their own silhouette, scales them to
  the same height and writes a side-by-side **plus a 50 % blend**. The blend is
  the single most useful artefact in the repo: it shows a proportion error
  immediately, where a side-by-side hides it.
* `tools/profile.sh` prints the left/right silhouette extent at 26 evenly
  spaced heights, as a fraction of figure height, so the two can be diffed
  numerically.
* `?hud=0` hides the overlay chrome — without it the HUD's own boxes land in
  the silhouette and poison both measurements.
* `?bg=magenta` + `?hud=0` is the pair to use for any silhouette work.

`tools/video.sh` renders the branded turnaround video (shot list in
`tools/video.mjs`, caption bar + encode in the shell wrapper).

## Conventions that matter when editing

* **Angle convention.** `onTorso(a, y, grow)` uses `x = rx·cos(a)`,
  `z = rz·sin(a)`; the character **front is `a = π/2`**. `surfaceShell` winds
  quads so this parameterisation produces outward normals with `flip: false`.
  Any shell whose `v` axis runs *downward* (e.g. the shorts legs) needs
  `flip: true` or it renders inside-out and shades black.
* **Everything sits proud of the body.** Decals (collar, placket, pocket,
  buttons) are placed with a `grow` value larger than the shirt's own `grow` at
  that height, otherwise they are swallowed by the garment shell.
* **Hair strands must close to a point.** `sheetW`/`sheetT` are multiplied by
  `tipTaper` so the swept tube ends in a single vertex — an open tube shows its
  hollow interior.
* **One curtain, then detail strands.** The back of the hair is a single
  continuous `surfaceShell` curtain; layering dozens of equal strands instead
  makes the hem read as a grass skirt rather than drawn hair.
* **Winding depends on how `point` is written, not on the part.** `surfaceShell`
  winds outward for a `headSurface`-driven shell with `v` running *down* the
  head, but a hand-written `out.set(...)` formula with the same `v` direction
  comes out the other way. The back curtain needs `flip: true`; the fringe
  needs `flip: false`. Get it wrong and the mesh is silently back-face culled —
  the fringe was invisible for several iterations and the "fringe" on screen
  was really the scalp shell's scalloped edge.
* **`paintAlongV` reads `uv.y`.** Any shell whose `uv` scales `v` (e.g.
  `[u * 4, v * 2]`) clamps to the last colour stop past `v = 0.5`, so half the
  surface ends up one flat tone.
* **Procedural textures must tile seamlessly.** `clothTexture`'s diagonal
  gradient repeated 4×4 across the pillow and read as a diamond grid over the
  cushion; it is a radial gradient now. Anything with a directional gradient
  will show its tile boundaries.
* **Hair lengths are metres from the head centre.** `headSurface` returns
  R-scaled vectors while the tip literals are plain metres, so the two live in
  the same space. `HEM_Y = -0.98` puts the hem at world y ≈ 0.59 — mid-thigh,
  which is where the reference's hair actually ends. Measuring this off a
  downscaled crop is treacherous; measure on the full-resolution image and
  convert with the foot-to-hair-top distance.
* **Never straight-`lerp` two points on a sphere.** The chord cuts *inside*
  the surface, so the scalp shell pokes through the fringe. Interpolate the
  polar angle and re-project with `headSurface` (this is what made the fringe
  read as a row of teeth).
* **Outer layers must sit proud of the inner one.** The broad locks were
  hidden inside the curtain until their outward bulge exceeded the curtain's;
  the silhouette is carried by the *outermost* surface, so that is the one to
  tune.
* `tools/bbox.mjs` prints the world bounding box of every named part — it is
  how the over-long hair hem was found.
* **Root strands *outside* the scalp shell.** The scalp sits at
  `R * capSwell` (1.10–1.15 R). Locks rooted below that are buried inside it,
  which is what made the hair read as a smooth helmet for so long.
* **Colour-match by sampling, not by eye.** The hair ramps were producing
  `#6360a0` against the reference's `#7d7bb5`, and the skin `#dec8cb` against
  `#fdf6f4`. `magick <img> -format '%[pixel:p{x,y}]' info:` on both images
  settles it in one command.
* **A flat lock is lit as one plane.** `shadeAcrossU` fades the vertex colour
  toward the ribbon's thin edges so the same geometry reads as a rounded
  strand.
* **Bake fine strand detail into a texture, not into geometry.** The hair mass
  is one ridged `surfaceShell` wearing `hairStrandTexture()` — a tiling canvas
  of soft grooves. That reads as strands at every distance for a fraction of
  the triangles that hundreds of swept locks would cost.
* **Procedural print must wrap exactly once.** The garments map uv as
  `u * 2.2, v * 2.2`, so the fabric texture repeats `1 / 2.2` times; any other
  repeat slices the motifs at the surface seam.
* **Check limbs against garments.** The thighs were wider than the shorts at
  the hip, so they punched through as a pale band across the waist. `bbox.mjs`
  showed it immediately.
* **Close open tubes.** The sleeve's cuff was an open ring, so from three-
  quarter views the outline shell's interior showed through as a dark flat
  wedge. Blending the cuff radius down onto the arm closes it.
* **Turn on `receiveShadow` for the character.** The meshes only cast by
  default, so the cel shading was perfectly flat. Self-shadowing (with
  `normalBias ≈ 0.03`) is what makes the hair read as sitting on the
  shoulders — and it needs a matching lift in the hemisphere/ambient fill, or
  the chest under the chin goes black.
* **`shadeAcrossU` peaks at `u = 0.25`, not `u = 0`.** `hairStrand` builds its
  cross-section as `A + w·cos(a)·B + h·sin(a)·C`, so `u = 0` / `0.5` are the
  thin edges and `u = 0.25` is the *outward face*. Peaking the falloff at 0
  darkens the surface the camera sees and brightens the hidden edge — that bug
  alone kept the hair two stops darker than its own colour ramp.
* **`headSurface` puts `x = -cos(phi)·sin(theta)`.** Any lock direction written
  as `(cos(a), 0, sin(a))` is mirrored, and every lock sweeps across the face.
  It must be `(-cos(a), 0, sin(a))`.
* **Paint the hair mass by height, not by `v`.** Each lock runs from a
  different root to a different tip, so a `v`-keyed ramp puts the gloss band at
  a different height on every one and the mass loses its highlight.
  `paintByHeight(geo, stops)` takes world-`y` stops instead.
* **A sub-range of a ramp is not a ramp.** The fringe occupies only the top
  0.13 m of the head — exactly where `MASS_RAMP` puts its highlight — so painted
  from that ramp the bangs came out near-white and vanished against the skin.
  The fringe needs its own `FRINGE_RAMP`.
* **Fringe = one sheet; the hanging mass = overlapping locks.** Loose locks
  over the brow always read as loose strands over the face; a smooth sheet with
  a pointed lower edge and a parting is what a painted fringe looks like. The
  reverse is true below the jaw: a sheet there reads as a board.
* **Every garment detail must track the shirt's own `grow`.** Once the shirt
  became A-line, a fixed `grow` on the collar/placket/pocket/buttons left them
  all buried inside it. `shirtGrow(y)` exists so each detail sits proud of the
  shirt *at that height*.
* **A tube needs a cap.** The shirt is a closed cylinder, so its top edge left
  a ring of daylight around the neck. `shirtYoke` slopes the shoulder from the
  shirt radius onto the neck radius.
* **Watch for a shadowed local named `g`.** The outfit builder's group is
  `const g = new THREE.Group()`; a local `const g = shirtGrow(...)` shadows it
  and the failure mode is a runtime `x.add is not a function` at boot.
* **`tubeAlongCurve` leaves both ends open.** An open end shows the outline
  shell's interior as a dark ellipse — the raised arm did exactly this, and it
  is very visible in the video's face close-up. Taper the radius to a point over
  the last few percent of `t` so the tube closes inside the deltoid / the hand;
  a bigger deltoid does *not* fix it, because the hollow is a ring, not a cap.
* **A bow loop has to be pinched at both ends.** Solid ellipsoids read as a
  pair of rabbit ears; a ribbon swept around a closed path reads as doughnuts.
  `bowPetal()` sweeps a flat cross-section along a path that leaves the knot as
  a point, swells, and returns to a point — that is what reads as folded cloth.
  The petals also need a darker outline than the kerchief, or the two whites
  merge.
* **A garment hem is a *step*, not a line.** The shirt and shorts only read as
  two garments when the shorts are measurably wider than the shirt hem (the
  reference is ~0.02 m wider). Matching radii plus a shadow band still reads as
  one nightdress.
* **Cel shading.** `toonGradient(steps, softness, floor)` builds the ramp.
  `floor` keeps downward-facing surfaces (jaw, under-chin) from reading grey.
* Outlines are inverted-hull shells expanded along **vertex normals** in the
  vertex shader (`materials.js`), which also works on non-convex shapes.

## Deliverables

```bash
node tools/showcase.mjs        # branded stills -> showcase/

# two aspect ratios, 1600 px wide, each H.264 + VP9
tools/video.sh --w 1600 --h 1200 --out showcase/yuuka-4x3.mp4     # 4:3
tools/video.sh --w 1600 --h  900 --out showcase/yuuka-16x9.mp4    # 16:9

tools/video.sh --encode-only --w 1600 --h 900 --out ...   # re-encode, no re-render
```

`tools/video.mjs` scripts the camera through a 360° turntable, a face
close-up, a back three-quarter and a hero push-in, and freezes the idle
animation so the only motion is the camera. Frames land in
`video/frames-<W>x<H>/` (git-ignored).

**Shot distances are derived, not hand-tuned.** `FIT(subjectH, fill)` returns
the camera distance that makes a subject of that height occupy `fill` of the
frame, from the camera's 30° *vertical* field of view. Because the FOV is
vertical, the same shot list frames the character identically at 4:3 and 16:9 —
the two videos differ only in how much studio sits either side of the subject.
Do not hard-code distances per aspect.

`tools/video.sh` lays a full-width black caption bar across the bottom of every
frame with the model name in large white type and the tool name beneath it. Bar
height and both font sizes are fractions of the frame height (14 %, 4.5 %,
2.2 %), so the credit reads the same on a 900-tall 16:9 frame as on a 1200-tall
4:3 one.

## Deploying

The repo is public and the built site lives at the repo root
(`index.html` + `dist/`), so GitHub Pages only needs pointing at the branch:

```bash
gh api -X POST repos/<owner>/<repo>/pages \
  -f 'source[branch]=deepseek-v41-flash-high_devin-cli_yuuka3d' -f 'source[path]=/'
```

> Note: from the container this project was authored in, every
> `api.github.com/repos/<owner>/<repo>` request returns 404 (the same paths
> work for other accounts), so Pages could not be enabled programmatically
> here. Run the command above from an unrestricted machine, or enable Pages in
> **Settings → Pages** with branch `deepseek-v41-flash-high_devin-cli_yuuka3d`,
> folder `/`.

## Honest ceiling

The target is a hand-painted 2D illustration; this is real-time procedural
3D with no sculpting, no textures authored in an image editor and no external
assets. It captures the design read (silhouette, palette, outfit construction,
halo/bow/pillow, cat-print fabric) but will not reach illustration fidelity.
The gap that remains is fine surface detail — cloth drape, individual hair
strands, facial modelling — which is where the remaining points live.
